# Bettbox 额外规则
#
# 每行一条 mihomo 规则，会被插到 rules 的【最前面】（优先级最高）。
# 改完这里，GitHub Action 会自动重建 bettbox/mihomoScript.js。
# 用完的临时规则记得删掉，否则会一直生效。
#
# 格式示例：
#   DOMAIN-SUFFIX,example.com,美国
#   DOMAIN,sub.example.com,GitHub
#   DOMAIN-KEYWORD,foobar,默认代理
#
# 组名必须是：默认代理 / 直连 / 香港 / 日本 / 美国 / 新加坡 / 台湾 / 韩国 /
#             GitHub / AI / Google / YouTube / Netflix ...

# ===== Tailscale 内网直连 =====
# 100.64.0.0/10      Tailscale IPv4 地址段（与运营商 CGNAT 共用，公网服务极少使用）
# fd7a:115c:a1e0::/48 Tailscale IPv6 ULA 段
# ts.net             MagicDNS 后缀
# no-resolve：纯 IP 规则不触发本地 DNS 解析，避免每个连接多一次查询
# ⚠️ TUN 模式下这三条只是兜底：真正让 tailnet 不进 TUN 的是 Bettbox 界面
#    「绕过私有网络」地址列表里的 100.64.0.0/10 与 fd7a:115c:a1e0::/48
#    （Windows 下 TUN 排除路由只认这个列表，开关关闭则清空）
# ⚠️ 系统代理模式下 *.ts.net 要在界面「排除域名」里加，否则域名交给 mihomo
#    解析会失败（MagicDNS 只有系统 DNS 能解）
IP-CIDR,100.64.0.0/10,直连,no-resolve
IP-CIDR6,fd7a:115c:a1e0::/48,直连,no-resolve
DOMAIN-SUFFIX,ts.net,直连

# Tailscale 自身流量（控制面 / DERP / UDP 打洞）必须直连：
# TUN 模式下若被代理，UDP 打洞失败，只能走 DERP 中继（tailscale ping 显示 relay）
# 系统代理模式下 tailscaled 不走代理，这条不生效也无害
PROCESS-NAME,tailscaled.exe,直连

# 临时：morphllm 走美国
DOMAIN-SUFFIX,morphllm.com,美国

# Antigravity 全进程走 AI：登录 / 推理 / 更新 / 扩展统一出口，避免登录地与调用地不一致触发风控
# 按安装路径匹配：AI 请求实际由 resources\bin\language_server.exe 发出，
#   PROCESS-NAME,Antigravity.exe 只管得到主程序；路径含 \antigravity\ 的进程全部命中
# ⚠️ 进程类规则依赖 Bettbox 界面「查找进程」= 开（always）；
#    脚本里写 find-process-mode 会被界面覆盖，写了也不生效
# ⚠️ 系统代理模式下 language_server.exe 不读系统代理，请用 bettbox/Antigravity-proxy.cmd 启动
PROCESS-PATH-REGEX,(?i)\\antigravity\\,AI

# ===== ChatGPT / OpenAI 登录所需的 Arkose 验证 =====
# geosite category-ai-!cn 未收录 arkoselabs，缺这两条会在登录页卡在验证码
# （小火箭靠 ai-extra.list 补同一个洞）
DOMAIN,openai-api.arkoselabs.com,AI
DOMAIN-SUFFIX,client-api.arkoselabs.com,AI
# OpenAI 自建服务器 IP，不在 geoip 库里
IP-CIDR,24.199.123.28/32,AI,no-resolve
IP-CIDR,64.23.132.171/32,AI,no-resolve
# 兜底：所有含 openai 的子域
DOMAIN-KEYWORD,openai,AI
